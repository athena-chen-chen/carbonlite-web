## Flow and recorded evidence

1. Login with an explicitly provisioned synthetic customer user. Record PASS/FAIL.
2. Create/open a new isolated synthetic workspace; verify it has no inherited records and is not shared with customers.
3. Upload the two-row first-sheet XLSX. Record synthetic source/document ID.
4. Run extraction; verify both quantities, units, province and ISO dates are preserved.
5. Open Draft Review; electricity is calculable, Water tracked-only. No false Water MISSING_FACTOR.
6. Select these two rows and confirm. Verify two rows created; repeat the same confirmation only if reachable and verify no duplicate records.
7. Open Data Records and verify the two imported records and copied source identifiers.
8. Open Calculation Results for the selected document.
9. Verify total 519.40 kgCO2e, Scope 2 519.40, other scopes zero.
10. Verify Water 18 m3 remains visible/tracked-only and excluded from the GHG total.
11. Open Technical Emissions Report; verify the same totals and Pilot Draft / version 0.1 / Not reviewed positioning.
12. Export CSV; verify both records, electricity 519.40, tracked Water semantics and safe text serialization.
13. Export PDF; inspect correct scope/totals/source evidence. Retain delivered CSV/PDF as dated files. They are draft operational outputs, not signed immutable compliance records.
14. Delete ONLY the disposable synthetic source document through the supported app flow. Never delete customer data as a test.
15. Reload Data Records and a workspace/selected-record report; verify the two ActivityData IDs, source provenance and 519.40 total persist. The deleted document may no longer be selectable, so do not confuse lost document selection with deleted accounting records.
16. GET `/api/health/live`: expect 200 without authentication.
17. GET `/api/health/ready`: expect 200 with healthy database; infrastructure timeout >=5 seconds.

Source durability restart/redeploy checks use a separate retained synthetic source BEFORE deletion, as described in the deployment checklist. Do not expect deleted Document metadata to remain downloadable.

## Pilot user instructions

1–5 separate clean customer workspaces; typically fewer than 100 documents/customer; ActivityData preferably well below 10,000 initially; low confirmation concurrency and manual support. These are operating expectations, not hard architecture limits. If a large staged confirmation fails, select/import smaller batches. If initial spreadsheet staging itself fails, split the input file. The default JSON byte ceiling is smaller than the DTO's 10,000-row cap; no automatic byte batching is promised.
